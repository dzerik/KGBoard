# KGBoard: объяснение подсветки и диагностика

Статус: пакет B для проверки. Зависит от модели сценариев и назначений пакета A.
Общие ограничения: [product evolution](2026-11-16-product-evolution-design.md).

## Пользовательский результат

На вопрос «почему сейчас этот цвет?» плагин отвечает конкретным сценарием, владельцем
проекта и устройством. Отсутствие цвета тоже объясняется: выключено, unfocused dim,
недоступное устройство, неназначенная цель, unknown analysis или отсутствие события.

## Единое решение renderer и объяснения

Policy формирует `LightingDecision`: готовые кадры и explanation для каждого устройства.
Вычисление targets, сортировка приоритетов, видимость и внешние overlays выполняются
один раз. Отдельный упрощённый алгоритм «главного эффекта» для UI не вводится.

Decision содержит render revision, session, device binding, project owner, выбранные
правила и их targets, видимые LED, перекрытые правила и причины. Для частично
перекрытого правила показывается частичная видимость. Indicator/ambient/mirror,
Preview, Disabled, dim и shutdown учитываются так же, как при построении кадра.
Для idle явно пишется «Нет активных сигналов».

Цвет и объяснение не расходятся при равных приоритетах: tie-break тот же, что в кадре.
Никакие Project/PSI/Swing объекты не попадают в опубликованный snapshot.

## Доставка не равна намерению

Writer сообщает Sent/Failed с session, device binding и frame revision только после
результата I/O. Offer означает Pending. Устаревшие acknowledgements игнорируются;
coalesced кадры не объявляются отправленными. Совпавший с кешем кадр ссылается на
последнюю успешную запись этой же сессии.

Delivery-only событие обновляет diagnostics snapshot без нового render, animation
reschedule и повторной отправки. Это исключает обратную связь frame→ack→frame.
Ошибка показывает причину и следующий retry; ручной Disconnect отличается от сбоя.

## Нативный интерфейс

Компактный status widget: RGB и короткое состояние. Детали не растягивают status bar.
Нажатие открывает popup с текущим устройством, причиной цвета, Connect/Disconnect,
Open Settings и Open Diagnostics. Прямое скрытое переключение соединения удаляется.

Tool Window KGBoard содержит:

1. Соединение, устройство, owning project и время последней успешной отправки.
2. «Сейчас отображается» и список ожидающих/перекрытых сигналов.
3. Analysis: Unknown/Indexing/Not applicable/Errors/Warnings/Clean.
4. Недавние ошибки и действия восстановления, доступность optional-интеграций.
5. Copy Diagnostics и Clear History.

Если устройство или сигнал не выбраны, показывается объяснение и одно подходящее
действие. UI использует обычные Swing/platform components; UI DSL остаётся для
форм редактирования настроек, не для динамической панели наблюдения.

## Ограничение данных и частоты

История хранит последние100 значимых переходов в памяти приложения. Animation frames
не добавляются по одному в историю. Одинаковые повторяющиеся ошибки coalesce с count
и lastSeen. После перезапуска история пуста. Нет постоянного фонового сброса на диск.

UI updates coalesce и происходят не чаще4раз/с; статичный одинаковый presentation не
обновляется. Подписки снимаются при закрытии панели/проекта, queued EDT updates
проверяют lifetime. Закрытие UI не останавливает runtime.

Copy Diagnostics — явное действие пользователя. Текст содержит IDE/plugin versions,
capabilities, состояния соединения, session/revisions, размеры целей, причины и
последние ошибки. Полные пути, содержимое файлов, serial/location и ветки по умолчанию
не копируются. В интерфейсе серийный идентификатор скрыт до раскрытия деталей устройства.

## Критерии приёмки

- Для нескольких процессов и нескольких устройств explanation соответствует каждому
  отправленному кадру, включая частичное покрытие, равные приоритеты и разные роли.
- Preview/dim/Disable/shutdown объясняются внешней политикой, а не последним IDE event.
- Fake transport блокирует write: UI показывает Pending; успех появляется только после write.
- Старый session ack не меняет текущую доставку.1000 acknowledgements не создают новых writes.
- История не превышает100 записей; анимация не создаёт поток history entries/EDT updates.
-20 циклов open/close Tool Window не увеличивают число подписчиков.
- Copy Diagnostics не содержит полного project path, file content и hardware identifiers.
