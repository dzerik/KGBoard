# KGBoard: профили и интенсивность подсветки

Статус: письменный дизайн пакета D утверждён пользователем. Зависит от typed rules/targets пакета A и использует
решение policy из пакета B и Git-состояния пакета C. Общие ограничения:
[product evolution](2026-11-16-product-evolution-design.md).

## Профиль как шаблон настроек

Профиль меняет внешнее представление сигналов: включение правил, цели, цвета,
периоды/длительности, две категории яркости и animation policy. Runtime facts,
приоритеты и lifecycle операций от профиля не зависят.

Встроенные IDs: minimal, debug, quiet. Пользователь может создать копию, изменить
имя, сохранить изменения или удалить собственный профиль. Встроенные определения
не изменяются; их настройка создаёт пользовательский вариант.

Профиль содержит отдельные app/project templates. На странице App применяются
только app-поля, на странице Project — только project-поля. UI показывает scope
и список изменений до Apply; скрытой записи в другой scope нет.

## Точные начальные профили

Цвета используют текущую палитру: success#00C853, failure#FF1744, warning#FFD600,
run#00E676, debug#651FFF, tests#2979FF, stop#FF9100. Цель для общих app-сигналов — All;
после выбора пользователь может назначить группу или клавиши. Ошибки project-analysis
и Git conflict используют именованную Esc; при её отсутствии цель остаётся явно
неразрешённой, без подстановки All.

| Параметр | Минимальный | Отладка | Тихая подсветка |
|---|---|---|---|
| Persistent brightness |25% |40% |15% |
| Notification brightness |60% |70% |35% |
| Animation policy |Static |Full |Static |
| Terminal duration |1.5с |2с |1.2с |
| Build/Test progress |Выключен |Включён |Выключен |
| Build/Test result |Success и failure |Success и failure |Только failure |
| Run/Debug active |Выключен |Включён |Выключен |
| Breakpoint visual |Выключен |Включён |Выключен |
| Save/Indexing/TODO visual |Выключен |Выключен |Выключен |
| Low Memory visual |Включён |Включён |Включён |
| Project analysis |Errors/Warnings |Errors/Warnings |Только Errors |
| Project Git |Только conflict |Conflict/Dirty/Ahead/Behind/Diverged |Только conflict |
| Project shortcut hints |Выключены |Debug/Search |Выключены |

Существующие branch rules не удаляются профилем; их отображение выключается rule flag
во встроенных профилях. Помодоро не запускается и не останавливается выбором профиля;
его visual rules подчиняются выбранной интенсивности и animation policy.

## Границы применения

Профиль не содержит host/port, auto-connect/reconnect, skipCustomMode, device bindings,
multi-device topology, версии схемы, capabilities и историю diagnostics. Не меняет
длительности/число циклов/включение Pomodoro, текущую фазу и таймер. Фокус и shutdown
оставляет пользовательским настройкам. Не содержит ProjectId и filesystem paths.

Выбор профиля сначала меняет draft и показывает изменения. Cancel их отменяет,
Apply проходит обычную полную валидацию. Нет прямого apply в singleton из combo listener.
После ручного изменения параметров picker показывает «Пользовательский», если значения
не совпадают с шаблоном; один только reconnect не меняет статус профиля.

## Яркость и анимация

Два значения имеют диапазон0–100 и legacy-default100. Persistent применяется к idle,
branch background и длительным индикаторам; Notification — к конечным результатам,
save/memory и transition-сигналам. Категория правила задана каталогом, а не наличием
animation tick. Яркость масштабируется один раз до композиции; focus dim дополнительно
уменьшает обычный idle согласно настройке. Preview сценария использует его draft-канал.

Static сохраняет смысл и deadline эффекта, но не создаёт периодическую анимацию:
Pulse/Wave используют основной цвет, Flash — статичную подсветку до конца deadline,
Gradient — начальный цвет фазы. Progress меняется только при фактическом изменении
progress. Автономные Rainbow/Wave не включаются встроенными профилями.
Full сохраняет существующую математику эффектов.

## Хранение и совместимость

Пользовательские профили имеют UUID и schemaVersion, хранятся средствами платформенного
XML serializer. Имя уникально без учёта регистра внутри scope. Каталог встроенных
профилей версионируется отдельно. Неизвестные поля/IDs не исполняются и не превращаются
в разрешение писать All. Новый профиль создаётся из whitelist appearance-полей,
а не сериализацией полного RuntimeSettings.

Импорт/экспорт внешних файлов и обмен профилями через сеть в этот пакет не входят.
Existing user groups и старые цвета сохраняются при обновлении; встроенный профиль
не применяется автоматически к существующей установке.

## Критерии приёмки

- Каждое значение встроенных шаблонов закреплено тестом; apply не меняет endpoint,
  device binding, timer phase/durations и настройки другого scope.
- Выбор → редактирование → Cancel не меняет persisted/runtime configuration.
-0/25/100% дают ожидаемые каналы;100%/Full воспроизводят прежние кадры.
- Static не держит33ms loop, deadlines и остаток Pomodoro продолжают обновляться.
- Preview и обычный render при одинаковом draft-правиле имеют одинаковую интенсивность.
- Сохранение/перезапуск/переименование/удаление пользовательского профиля проходят XML round-trip.
