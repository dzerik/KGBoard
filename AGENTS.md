# Repository Guidelines

## Структура проекта

KGBoard — плагин IntelliJ Platform, который отображает события IDE через RGB-подсветку устройств OpenRGB. Основной код находится в `src/main/kotlin/com/kgboard/rgb/`: `client/` реализует TCP-протокол и подключение, `effect/` управляет эффектами и композициями LED, `bridge/` связывает события IDE с эффектами, `settings/` содержит настройки и UI. Каталоги `layout/`, `preset/` и `pomodoro/` отвечают за раскладку клавиатуры, группы клавиш и таймер.

Ресурсы и дескрипторы плагина находятся в `src/main/resources/`; регистрации расширений — в `META-INF/plugin.xml` и `META-INF/kgboard-git.xml`. Тесты расположены в `src/test/kotlin/` и повторяют структуру пакетов исходного кода.

## Сборка, тестирование и разработка

Используйте JDK 21 и включённый Gradle Wrapper:

- `./gradlew buildPlugin` — собрать ZIP в `build/distributions/`.
- `./gradlew test` — выполнить тесты; HTML-отчёт появится в `build/reports/tests/test/`.
- `./gradlew runIde` — запустить изолированную IntelliJ IDEA с установленным плагином.
- `./gradlew test --tests '*OpenRgbProtocolTest'` — запустить отдельный набор тестов.

Для ручной проверки подсветки запустите OpenRGB с включённым SDK-сервером; стандартный TCP-порт — `6742`. CI выполняет сборку плагина и тесты.

## Стиль кода и именование

Соблюдайте Kotlin Coding Conventions и `.editorconfig`: UTF-8, LF, четыре пробела для Kotlin/XML, два для JSON/YAML, завершающая новая строка. Имена классов и файлов используйте в `PascalCase`, функций и свойств — в `camelCase`. Документируйте публичные API через KDoc, сохраняйте функции небольшими. Отдельный Kotlin-линтер или форматтер в Gradle не настроен.

## Правила тестирования

Используются JUnit Jupiter 5 и MockK; Gradle запускает JUnit Platform. Называйте тестовые классы `*Test`, методы — понятными описаниями проверяемого поведения, включая Kotlin-имена в обратных кавычках. Добавляйте проверки протокола, вычисления эффектов и сохранения настроек при изменении соответствующей логики. Обязательный процент покрытия не установлен. Изменения интерфейса и интеграции проверяйте также через `runIde`.

## Коммиты и pull request

Следуйте формату истории: `feat: описание`, `fix: описание`, `refactor: описание`, `docs: описание`, `chore: описание`, `perf: описание`, `test: описание`. Дополнительное пояснение отделяйте пустой строкой. Используйте тематические ветки, например `feat/key-groups`.

Перед каждым коммитом повышайте `pluginVersion` в `gradle.properties` по SemVer и обновляйте `CHANGELOG.md`, как требует `CLAUDE.md`. Для документации выбирайте PATCH. В PR опишите проблему, результат и выполненные проверки; укажите связанный issue, если он есть. Для изменений UI приложите снимки экрана. Подробности участия и сообщения об уязвимостях смотрите в `CONTRIBUTING.md` и `SECURITY.md`.
